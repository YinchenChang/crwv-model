### 3. 架構

```
company.json ──► build_xlsx.py ──► 完整版 xlsx（照舊）
                                     │
                                     ├─► scripts/lean.py：依「精簡版目標清單」（具名範圍）計算公式依賴鏈，
                                     │   以 LibreOffice UNO 刪除依賴鏈外的列與分頁（LibreOffice 刪列時會自動改寫所有參照），
                                     │   刪除說明欄、合併剩餘小分頁 ─► 精簡版 xlsx
                                     │      └─► recalc → fix_datatable → fix_outline → verify_ooxml
                                     └─► scripts/export_json.py：以 LibreOffice 對 3 情境 × 2 模式重算精簡版，
                                         依具名範圍匯出 JSON ─► build_html_portable.py --lean 內嵌進檢視器模板 ─► 精簡版 HTML
```

- **不另開模型程式碼**：精簡版 Excel 由完整版刪減而成，公式就是同一批。完整版任何計算的修改會自動帶到精簡版。新增的只有刪減腳本、匯出腳本和檢視器模板（顯示用）。
- **檢視器**：一個 HTML 模板，加上約 200–300 行只做顯示的 JS（取值、格式化數字、切換情境）。不含任何計算，連差距百分比、判斷句都來自 Excel 公式。依已決定事項 8，這個檢視器就是 5b 的雛形：(A) 下直接取代 5b；(B) 下 5b 沿用它。
- **分頁（7 個）**：摘要｜輸入｜收支與融資（各期收支＋新債與新股）｜運營與債務（產能與收入＋既有債務）｜損益與評價｜季度追蹤｜檢查與名稱（5 項檢查＋名稱清單＋版本一行）。先做「只刪不合併」（10 個分頁），合併另外驗證。
- **主要風險**（第 2 輪先測）：
  - LibreOffice 刪列後，模擬運算表會被改寫成 `TABLE()`，`fix_datatable.py` 目前以固定位置還原，要改為依標籤定位。
  - `<sheetPr>` 子元素順序（勿改 4）與 outline 需要重跑。
  - 跨分頁搬移時，參照的改寫需要逐格驗證。
  - 若刪減方式不可行，改用 `build_xlsx.py --profile lean`（在同一支程式加開關）。這樣精簡版多約 3–5 輪，(B) 的並行成本也會再上升；屆時重新估算並回報。
